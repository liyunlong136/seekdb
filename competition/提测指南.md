## 三、你在终端执行的推送命令

### 前提：SSH 走 443 端口

本机 HTTPS 出网被系统 TLS 层拦截，Git 走的是 `ssh.github.com:443`。
`~/.ssh/config` 已配置好，直接可用：

```
Host github.com
  HostName ssh.github.com
  Port 443
  User git
  IdentityFile ~/.ssh/id_ed25519
  IdentitiesOnly yes
  StrictHostKeyChecking accept-new
```

若你在别的机器上执行，按 `~/.ssh/config` 内容补一份即可。

### 2. `fix/ddl-identifier-escaping` —— Bug 修复题（对应 #1469）

修的是 #1469：**share 模块不允许 include 上层 sql 模块**。

- 新增 `common::escape_sql_identifier()`（`src/oblib/lib/string/ob_sql_string.h`），
  把标识符转义下沉到 oblib；
- `src/share/ob_ddl_common.cpp` 直接用 oblib 的实现，`share` 不再依赖 `sql`；
- `src/sql/ob_sql_utils.cpp` 保留 `ObSQLUtils::generate_new_name_with_escape_character`
  作为 SQL 层入口，改为委托给共享实现，两层转义结果始终一致；
- 注册已有但从未运行的回归用例 `vector_index.vector_index_identifier_quoting`。

**实测核验**：扫描 `src/share` 全部 668 个源文件，**无任何** include 上层模块；
转义行为与原实现逐字节一致（8 组用例）。

### 3. `perf/filter-equivalence-selectivity` —— 性能优化题

针对 12 个 ANN 过滤性能 issue 的**共同根因**：

> ANN 执行策略由**单个选择率估计值**决定
> （`ObVectorIndexUtil::set_adaptive_try_path` 拿它跟
> `DEFAULT_PRE_RATE_FILTER_WITH_IDX` / `_WITH_ROWKEY` 这些**悬崖阈值**比）。
> 估计值来自过滤条件的**语法形式**，于是语义等价的过滤条件会落到不同的
> 选择率估计器上，得到不同的估计值，进而在悬崖两侧选到完全不同的 ANN 路径。

修法是在 rewrite 层补上**语义**那一半（原来只有语法比较，`same_as()`）：

- 新增 `ObFilterCanonicalizer`（`src/sql/rewrite/ob_filter_canonicalizer.{h,cpp}`），
  把列上的 IN 列表折叠成等价区间：
  `col IN (1,2,...,300)` → `col >= 1 AND col <= 300`
  两种写法因此走同一个区间估计器，得到同一个选择率、同一条 ANN 路径；
- 折叠只在**可证明选中相同行**时进行：左值必须是普通列引用，值列表必须是
  **连续递增的整数字面量序列**（`IN (0,5,10)` 这类跳值列表会被跳过）；
- 挂在 `ObTransformSimplifyExpr::do_canonicalize` 里，紧挨 `push_not` /
  `remove_duplicate_exprs` / `pull_similar_expr`，因此发生在选择率计算与区间图构建**之前**。

**回归覆盖**：新增 `vector_index.vector_index_filter_equivalence`，用
`V$OB_PLAN_CACHE_PLAN_STAT` + `__all_virtual_sql_plan` 断言两种写法的
plan operator 与 cardinality 一致，并覆盖三种不应折叠的列表。
